# 기능 명세

## 대시보드 `/`
서비스 소개, 검색, 최근 문제, 고객 유형 필터, 분야별 건수와 마지막 갱신 시각을 표시한다. Mock 자료는 모든 관련 화면에서 테스트 데이터로 식별한다.

## 문제 탐색 `/problems`
키워드, 고객 유형, 분야, 기술 태그, 기관, 예산 범위, 근거 강도, 2~4주 구현 가능 여부를 필터링하고 최신순 페이지네이션을 제공한다. 카드는 문제명, 고객 유형, 분야, 기관, 출처, 근거 수준, 추정 난이도와 저장 동작을 표시한다. 알 수 없는 예산·날짜는 생성하지 않는다.

## 문제 상세 `/problems/[id]`
요약, 원문 근거와 위치·출처 링크, 불편, 요구 기능, 기관, 알려진 예산, 출처 문서, AI 해결 방향과 MVP를 표시한다. 공식 원문과 AI 추론을 시각적으로 구별한다. 인용이 확인되지 않으면 근거 부족으로 표시한다. 로그인 사용자는 저장할 수 있다.

## 아이디어 `/ideas`
선택한 문제를 바탕으로 프로젝트명, 대상, 기능, 기술, 개발 기간·비용 추정, 난이도, 2주·4주 범위, 검증 방법 및 위험을 제공한다. 추정과 제안은 공식 공고 값이 아님을 표시하고 복사와 Markdown 내보내기를 제공한다.

## 관심 문제 `/saved`
로그인 사용자만 자신의 저장 목록을 조회·삭제하고 메모와 관심 상태를 수정하며 문제를 선택해 비교한다. 인증과 데이터 격리는 서버 및 DB에서 강제한다.

## 관리자 `/admin`
서버에서 관리자 권한을 검증한다. API별 상태, 마지막 수집, 성공·실패·중복 건수, 분석 오류, 호출량·비용을 표시하고 수집 실행 및 실패 재시도를 제공한다. 중복 작업을 방지하고 실패 내역을 유지한다.

## 처리 규칙
수집은 공식 문서에 확인된 API만 사용하고 나라장터 요청 기간을 7일 이하로 분할한다. 원본 저장 후 분석하며 실패해도 원본을 보존한다. DIRECT는 원문에 명시된 내용, INFERRED는 추론, INSUFFICIENT는 확인할 근거가 부족한 경우다. 원문 인용과 위치를 확인하고 불일치는 사용자에게 드러낸다. 기업마당 자료를 자동으로 직접적인 B2B 구매 수요로 분류하지 않는다.

## 개발 단계와 산출물
환경 조사와 프로젝트 구성 → Mock MVP → 공식 API 검증 및 연동 → AI 분석 → 테스트·보안·문서·배포 준비 순으로 진행한다. 구현 시 README, PRD, ARCHITECTURE, API, DATABASE, USER_ACTIONS, 환경변수 예제, 마이그레이션, Mock과 테스트 및 실행·배포 가이드를 제공한다. 외부 인증이 필요한 항목은 발급 URL, 값, 환경변수, 이유, 확인 방법을 `USER_ACTIONS.md`에 기록한다.
